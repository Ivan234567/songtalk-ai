# План внедрения китайского языка (Chinese Mode)

Документ фиксирует продуктовые решения и поэтапный план добавления китайского режима в SongTalk AI (Speakeasy).

**Принцип:** одна инфраструктура, два режима обучения в одном аккаунте — English и Chinese. Переключение простое, без сложных анимаций.

**Связанные документы:**
- [opisanie-produkta.md](opisanie-produkta.md) — текущее описание продукта (English-first)
- [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md) — актуальный продуктовый контекст

---

## 1. Зафиксированные решения

| # | Решение |
|---|---------|
| 1 | **Упрощённый китайский** — Simplified Chinese (`zh-CN`) |
| 2 | **Караоке только для English** — в китайском режиме раздел скрыт |
| 3 | **Switch в хедере** дашборда |
| 4 | **Default: English** — без онбординга-выбора при первом входе |
| 5 | **HSK 1–6** для китайского вместо CEFR (A1–C2) |

### Что сознательно не делаем

- Караоке для китайского
- Traditional Chinese (繁體)
- Онбординг «выбери язык» при первом входе
- i18n UI (интерфейс приложения остаётся на русском)
- Phrasal verbs в китайском режиме (англоязычная концепция)

---

## 2. Концепция: два режима в одном аккаунте

```
learningLanguage: 'en' | 'zh'
        │
        ├─► Header switch: [ English | 中文 ]
        ├─► Sidebar (Караоке только при en)
        ├─► API: learningLanguage в header/body
        ├─► Промпты: шаблоны по языку
        └─► БД: фильтрация/разделение по language
```

### Общее (один аккаунт)

- Авторизация (Supabase Auth)
- Баланс и история расходов
- Backend JWT, API-инфраструктура
- Streak (активность в любом режиме считается)

### Раздельное (по `learningLanguage`)

| Область | English | Chinese |
|---------|---------|---------|
| Словарь | Свой | Свой |
| Категории словаря | Свои (`en`) | Свои (`zh` / 分类) |
| Сессии собеседника | Свои | Свои |
| Прогресс и аналитика | Свой | Свой |
| Переводчик | EN ↔ RU | ZH ↔ RU |
| Уровни сложности | CEFR A1–C2 | HSK 1–6 |
| Караоке | Доступно | Скрыто |
| Разделы словаря | Слова, идиомы, phrasal verbs | Слова, 成语 (chéngyǔ) |

### Core Learning Path

Для обоих режимов сохраняется обязательный маршрут:

```
AI-диалог → Словарь → Прогресс
```

Караоке остаётся опциональным модулем **только для English** (см. [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md)).

---

## 3. UX переключателя

### Расположение

Хедер дашборда, segmented control:

```
[ English | 中文 ]
```

### Поведение

- Default при первом визите: **English**
- При переключении: короткий toast («Режим: китайский» / «Режим: английский»)
- Контекст обновляется без полной перезагрузки страницы
- Выбор сохраняется в профиле Supabase (`user_profiles.learning_language`)

### Визуальная подсказка

- Подпись «Изучаю: English / 中文» (опционально, в хедере или приветственном блоке)
- Лёгкий accent-цвет по режиму (опционально, без тяжёлых анимаций)

### Навигация

| Раздел | English | Chinese |
|--------|---------|---------|
| Главная | ✓ | ✓ |
| Собеседник | ✓ | ✓ |
| Словарь | ✓ | ✓ |
| Караоке | ✓ | ✗ (скрыт) |
| Прогресс | ✓ | ✓ |
| Пополнение баланса | ✓ | ✓ |

---

## 4. Модель словаря для китайского

Английская трёхвкладочная модель не переносится один в один:

| English | Chinese |
|---------|---------|
| Слова (`user_vocabulary`) | 词语 — иероглиф(ы), **pinyin**, перевод RU, HSK-уровень |
| Идиомы (`user_idioms`) | **成语 (chéngyǔ)** — 4-иероглифные выражения |
| Phrasal verbs | **Не используется** — вкладка скрыта |

Кэш определений (`word_definitions_cache`): ключ `(word, language)`.

## 5. Ступени реализации

### Ступень 1 — Switch + контекст (оболочка)

**Цель:** пользователь видит переключатель, выбор сохраняется, UI реагирует на режим.

**Scope (frontend):**

- `LearningLanguageContext`: тип `'en' | 'zh'`, default `'en'`
- Persist в Supabase (`user_profiles.learning_language`)
- Switch в хедере дашборда: `[ English | 中文 ]`
- Sidebar: скрыть пункт «Караоке» при `zh`
- Адаптация текстов на главной/landing по контексту (где уместно)
- Toast при переключении

**Scope (backend):** не трогаем.

**Критерий готовности:**

- [x] Переключил на 中文 → пункт «Караоке» исчез из меню
- [x] Переключил обратно → «Караоке» снова виден
- [x] После refresh страницы выбор сохранён
- [x] English flow не сломан

**Оценка:** 1–2 дня.

---

### Ступень 2 — Свободный диалог на китайском

**Цель:** первый рабочий end-to-end сценарий — свободный чат с ИИ на китайском.

**Принцип разбиения:** каждый этап — один узкий PR, один тип проверки. Не смешивать backend-промпты, голос и переводчик в одной задаче.

**Оценка суммарно:** 2–4 дня (зависит от TTS/STT).

---

#### Этап 2.0 — Spike: TTS/STT для китайского (опционально, ~1–2 ч)

**Зачем:** снять главный риск до кодирования. Если TTS недоступен — заранее выбрать fallback.

**Scope:**
- Ручной тест AITUNNEL: Whisper с `language=zh`, TTS с китайским голосом
- Зафиксировать в roadmap или комментарии: model/voice id, которые работают

**Критерий:**
- [ ] STT распознаёт короткую фразу на китайском
- [ ] TTS озвучивает китайский текст (или зафиксирован блокер + plan B)

**Backend / frontend:** не трогаем.

---

#### Этап 2.1 — Прокидывание `learningLanguage` (инфраструктура)

**Scope (backend):**
- Helper `resolveLanguage(req)` → `'en' | 'zh'` (header `X-Learning-Language` или body)
- Default: `'en'` — English flow не ломается

**Scope (frontend):**
- Передавать `learningLanguage` из контекста в agent-запросы (`AgentTab`, shared fetch helper если есть)

**Не делать:** промпты, STT/TTS, переводчик.

**Критерий:**
- [ ] В режиме `zh` запросы уходят с `learningLanguage: 'zh'` / header
- [ ] В режиме `en` поведение как сейчас

**Оценка:** ~0.5 дня.

---

#### Этап 2.2 — Текстовый чат + reply hint на китайском

**Scope (backend):**
- `POST /api/agent/chat` — промпт «Speak only in Simplified Chinese…» при `lang=zh`
- `POST /api/agent/reply-hint` — подсказка на китайском при `lang=zh`

**Scope (frontend):**
- Без изменений UI (если 2.1 готов)

**Критерий:**
- [ ] 中文 → Собеседник (свободный режим) → ответы на упрощённом китайском
- [ ] Reply hint предлагает ответ на китайском
- [ ] English chat не сломан

**Оценка:** ~0.5–1 день.

---

#### Этап 2.3 — STT: распознавание китайской речи

**Scope (backend):**
- `POST /api/agent/stt`: при `lang=zh` передавать Whisper `language: 'zh'`

**Scope (frontend):**
- AgentTab: язык STT из контекста

**Критерий:**
- [ ] Голосовой ввод на китайском транскрибируется корректно
- [ ] English STT не сломан

**Оценка:** ~0.5 дня.

---

#### Этап 2.4 — TTS: озвучка китайского текста

**Scope (backend):**
- `POST /api/agent/tts`: китайский голос при `lang=zh` (id из этапа 2.0)

**Scope (frontend):**
- AgentTab: TTS-вызовы с учётом контекста

**Критерий:**
- [ ] Ответ ассистента на китайском озвучивается
- [ ] English TTS не сломан

**Оценка:** ~0.5–1 день.

---

#### Этап 2.5 — Переводчик ZH↔RU

**Scope (backend):**
- Направления `zh-ru` / `ru-zh` (параллельно EN↔RU, не заменяя)

**Scope (frontend):**
- `TranslatorPanel`: пары `zh-ru` / `ru-zh`
- В режиме `zh` переводчик по умолчанию ZH↔RU

**Критерий:**
- [ ] Переводчик ZH↔RU работает
- [ ] EN↔RU не сломан

**Оценка:** ~0.5–1 день.

---

#### Ступень 2 — итоговый чеклист

- [ ] 2.0 TTS/STT spike (или блокер зафиксирован)
- [x] 2.1 `learningLanguage` прокинут
- [x] 2.2 Chat + reply hint на китайском
- [ ] 2.3 STT для `zh`
- [ ] 2.4 TTS для `zh`

**Ступень 2 считается готовой**, когда все пункты итогового чеклиста отмечены.

### Ступень 3 — Словарь

**Цель:** лексика English и Chinese не смешивается; можно добавлять слова из диалога и переводчика.

**Scope (БД):**

- Колонка `language` (`'en' | 'zh'`, default `'en'`) в:
  - `user_vocabulary`
  - `user_idioms` (для 成语 в китайском режиме)
- Миграция Supabase
- Кэш: составной ключ `(word, language)` в `word_definitions_cache`

**Scope (backend):**

- `POST /api/vocabulary/define`, `/add` — промпты для китайского:
  - иероглиф(ы), pinyin, перевод RU, HSK-уровень, примеры
- Analyze idioms → analyze 成语 для `zh`
- List/export/import — фильтр по `language`
- SRS (`review-list`, `review`) — только слова текущего языка

**Scope (frontend):**

- Фильтр словаря по `learningLanguage` из контекста
- В режиме `zh`: две вкладки — **Слова** и **成语** (без phrasal verbs)
- Фильтр сложности: HSK 1–6 вместо CEFR
- Панель деталей: pinyin, иероглифы, примеры
- Добавление из переводчика и диалога с учётом языка

**Критерий готовности:**

- [ ] Слово из китайского диалога попадает в китайский словарь
- [ ] Английский словарь не изменяется при работе в режиме 中文
- [ ] SRS-повторение работает отдельно по языку
- [ ] 成语 можно добавить и просмотреть

**Оценка:** 3–5 дней.

---

### Ступень 4 — Прогресс и аналитика

**Цель:** замкнуть core path `AI → Словарь → Прогресс` для китайского.

**Scope (БД):**

- Колонка `language` в сессиях агента, `speaking_assessments`, completion-таблицах (roleplay, debate)

**Scope (backend):**

- `POST /api/agent/assess-speaking` — промпт и критерии для китайского:
  - тональность, грамматика, лексика, беглость, связность
- API прогресса — фильтр по `language`

**Scope (frontend):**

- ProgressHero, KPI, критерии, последние сессии — только текущий `learningLanguage`
- Главная дашборда: метрики (минуты, слова) по активному языку
- Streak — общий (активность в любом режиме)

**Критерий готовности:**

- [ ] Прогресс English и Chinese разделены
- [ ] Оценка речи после сессии работает для китайского
- [ ] Рекомендации и фокус-страницы учитывают язык
- [ ] На главной отображаются метрики текущего режима

**Оценка:** 3–4 дня.

---

### Ступень 5 — Roleplay и Debate

**Цель:** полный функционал собеседника для китайского (ролевые сценарии и дебаты).

**Scope (backend):**

- `POST /api/user-scenarios/generate` — генерация с `language: 'zh'`
- `POST /api/agent/roleplay-feedback`, `debate-feedback` — промпты под китайский
- `POST /api/agent/debate-topic-prepare` — валидация тем на китайском
- HSK 1–6 в настройках сложности вместо CEFR

**Scope (frontend):**

- Каталог сценариев/тем: на старте «Мои сценарии» + AI-create (без большого встроенного каталога)
- DebateSetupUI, roleplay UI — HSK, тексты под китайский
- Поля JSON: `titleZh`, `titleRu` и аналоги где нужно

**Критерий готовности:**

- [ ] Можно создать и пройти ролевой сценарий на китайском
- [ ] Дебаты на китайском с фидбеком (SBI-формат)
- [ ] Подсказки ответа учитывают шаги/позицию на китайском
- [ ] Сложность задаётся через HSK

**Оценка:** 5–7 дней.

## 6. Техническая схема (справочно)

### Frontend

```
frontend/
  lib/
    learning-language.ts      # тип, Supabase helpers, константы
  context/
    LearningLanguageContext.tsx
  components/
    header/
      LanguageSwitch.tsx      # [ English | 中文 ]
```

### Backend

```
learningLanguage ──► resolveLanguage(req) ──► getPrompts(lang)
                                              getAssessmentCriteria(lang)
                                              getTranslatorPair(lang)  // en-ru | zh-ru
```

### База данных (накопительно по ступеням)

| Таблица | Поле | Ступень |
|---------|------|---------|
| `user_vocabulary` | `language` | 3 |
| `user_idioms` | `language` | 3 |
| `word_definitions_cache` | `language` (в ключе) | 3 |
| agent sessions / completions | `language` | 4 |
| `speaking_assessments` | `language` | 4 |
| `user_profiles` | `learning_language` | 1 |
